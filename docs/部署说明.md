# 部署说明（公网访问）

> 目标：让 `https://minimize-creatures-grand-continental.trycloudflare.com` 保持可访问到 24:00。
> 本页写清楚：哪些进程要活着、各自在哪个窗口、环境变量怎么来、冷启动怎么从头跑。

---

## 一、必须保持运行的 3 个进程

| # | 进程 | 作用 | 监听 | 它长什么样 |
|---|---|---|---|---|
| 1 | **cc-switch.exe** | LLM 代理：把 Anthropic 兼容请求转给 deepseek | `127.0.0.1:15721` | 系统托盘里的 GUI 图标（可能没可见窗口） |
| 2 | **next start**（node） | 网页应用本体（生产模式） | `localhost:3000` | 一个终端窗口 |
| 3 | **cloudflared.exe** | 公网隧道 → 转发到 3000 | 公网 URL | 一个终端窗口（会打印 trycloudflare 地址） |

三者缺一不可，任何一个挂掉公网地址就不可用。

## 二、部署前置条件

- **Node.js** 已装（本机 v26.2.0）。
- **生产构建已完成**：`npm run build`（已执行，产物在 `web/.next/`）。
- **cc-switch 已启动**（提供 15721 代理 + 注入密钥）。
- **环境变量**（见下节）。

## 三、环境变量（重要：来自 cc-switch，不是系统级）

`ANTHROPIC_BASE_URL` 与 `ANTHROPIC_AUTH_TOKEN` 是 **cc-switch 注入到进程环境的**，Windows 用户级/系统级环境变量里没有。

| 变量 | 值 |
|---|---|
| `ANTHROPIC_BASE_URL` | `http://127.0.0.1:15721` |
| `ANTHROPIC_AUTH_TOKEN` | 你的 token（见 cc-switch 界面，或 `.claude/settings.local.json`） |
| `ANTHROPIC_DEFAULT_*_MODEL` | 可选，覆盖模型名 |

**含义**：从我（Claude Code）后台拉的 `next start` 能拿到这些变量（继承自 cc-switch 注入）。但**你自己开一个新终端跑 `npm run start`，默认拿不到**，必须手动设（见下）。

---

## 四、冷启动顺序（从头把公网地址跑起来）

前提：cc-switch 在托盘运行（`127.0.0.1:15721` 能访问）。

**终端 A —— 应用（生产模式）**（PowerShell）：
```powershell
$env:ANTHROPIC_BASE_URL = "http://127.0.0.1:15721"
$env:ANTHROPIC_AUTH_TOKEN = "<你的token>"
cd D:\workplace\AI面试官\web
npm run start
```
看到 `Ready` 即成功，监听 `localhost:3000`。

**终端 B —— 公网隧道**：
```powershell
D:\workplace\AI面试官\_tmp\tools\cloudflared.exe tunnel --url http://localhost:3000
```
它会打印一行 `https://xxx.trycloudflare.com` —— **这就是公网地址，记下它**（每次重启都会变）。

**浏览器**：打开公网地址，`Ctrl+Shift+R` 硬刷新测试。

---

## 五、保持到 24:00 的注意事项

1. **别重启 cloudflared** —— 每次重启会换一个新 URL，提交出去的地址就失效。
2. **别关 cc-switch** —— 它是 AI 后端的门。
3. **别停 `next start`**。
4. **电脑别休眠** —— 电源设置里把「睡眠」关掉，或插电并设置「接通电源时永不休眠」。

## 六、验证清单

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000        # 应 200
curl -s -o /dev/null -w "%{http_code}\n" https://<你的公网地址>/       # 应 200
# 应用内点「开始面试」应秒回（开场白不碰 AI）；「扫描软肋/分析面试官」约 10 秒出结果属正常
```

## 七、常见问题

| 症状 | 原因 | 处理 |
|---|---|---|
| `listen EADDRINUSE :::3000` | 有残留 dev 进程占 3000 | `netstat -ano \| grep :3000` 找 PID → `taskkill /PID <pid> /F` |
| 公网打不开、本地正常 | cloudflared 掉了 / URL 变了 | 检查终端 B，重跑拿到新 URL 并更新提交 |
| 点按钮没反应 | 跑的是 `next dev`（16 个 chunk + HMR，隧道下卡） | 改用 `npm run build` + `npm run start`（生产模式） |
| 应用报 LLM 错 | cc-switch 没跑 / 端口 15721 不通 | 检查托盘 cc-switch |
